# Antipatterns

GENERATED by `tools/gen.py` from [`spec/antipatterns.json`](../spec/antipatterns.json).

Failures that succeed: they report plausible wrong numbers, or destroy work while logging nothing unusual.

## 1. Treating a dropped poll as a dead VM

- **symptom:** supervisor sees an empty or failed poll, stops the session, re-allocates, re-uploads, restarts.
- **reality:** the websocket dropped; the detached job was running the whole time.
- **fix:** verify liveness with a RETRIED listing (or side-effect-free `colab usage`) before concluding anything; never `stop` in a failure path.
- **ref:** [04-supervisor-patterns.md](04-supervisor-patterns.md)

## 2. Believing an absence claim about tooling

- **symptom:** "there is no re-attach", "the CLI has no balance API", "shape X cannot be allocated", "flag Y needs a source build".
- **reality:** an absence claim is cheap to write, expensive to believe, and goes stale silently as the CLI and entitlements change.
- **fix:** when two sources disagree about whether a capability exists, test the one claiming it exists. Re-read `--help` after any upgrade. Record the CLI version with every capability claim.

## 3. Verifying through a filter

- **symptom:** a failed fix is indistinguishable from a successful one, so later work runs on inputs that were never replaced.
- **reality:** `... | grep -v ... | tail -8` hides the failure; the check reads a truncated log instead of the state that was supposed to change.
- **fix:** never filter the output of the step being verified. Re-read the changed STATE: a hash, a row count, `grep -c` on the VM's own files.

## 4. pkill -f / pgrep -f matching the caller

- **symptom:** restart script exits 15 with no output; or an idempotency guard always reports ALREADY_RUNNING.
- **reality:** -f matches the full cmdline of every process including the issuer; under `bash -c` that includes the whole script text.
- **fix:** script files, bracketed patterns ('[j]ob\.sh'), and never let the pattern appear elsewhere in the same command line.
- **ref:** [04-supervisor-patterns.md](04-supervisor-patterns.md)

## 4b. A pgrep guard on the thing being launched

- **symptom:** the guard reports ALREADY_RUNNING forever and the job never starts.
- **reality:** the pattern is inside the launching command line, so the bracket trick still self-matches. Unavoidable for a launch guard.
- **fix:** PID file + result-file check: three distinguishable states (running / already finished / not started).
- **ref:** [04-supervisor-patterns.md](04-supervisor-patterns.md)

## 4c. Assuming a timed-out call did nothing

- **symptom:** a retry double-launches, or completed work is abandoned.
- **reality:** an exec can hang on the REPLY while the command already ran on the VM. Most likely on the first call against a fresh session.
- **fix:** check state, not call status. Make retries idempotent by construction.

## 5. Two supervisors on one output directory

- **symptom:** interleaved writes, duplicated work, results that look fine and are a mix of two runs.
- **reality:** a background launch whose wrapper later errored looks like a launch that never happened, so it gets started again.
- **fix:** `flock -n` at the top. A background subshell `( ... ) &` inherits the parent's cmdline, so two identical `ps` lines may be one driver plus its helper -- check PPID.

## 6. Checkpointing only at the end

- **symptom:** a job whose only save is its last statement loses everything when the VM goes away before it.
- **fix:** checkpoint on state-change -- every completed unit, iteration or N steps -- to a temp path then `os.replace`, and download each one.
- **ref:** [04-supervisor-patterns.md](04-supervisor-patterns.md)

## 7. A checkpoint that cannot resume

- **symptom:** restore succeeds, then the job exits immediately at the saved iteration on a fresh VM.
- **reality:** the headline state file was backed up; the per-unit restart data it needs was not.
- **fix:** test restore on a FRESH machine. Snapshot the full restart state as one atomic tarball.

## 8. Overwriting one results archive per VM

- **symptom:** a campaign's earlier outputs disappear.
- **reality:** results come from a succession of VMs; each overwrite of results.tgz destroys the previous one.
- **fix:** merge downloads into a persistent bank directory; rebuild archives from the bank.

## 9. Banking only the summary, not the stream

- **symptom:** a long run across several VM lifetimes produces output covering only the last fraction of the work.
- **fix:** sync incremental outputs every poll, not just the final-state object.

## 10. Downloading a live file

- **symptom:** a database or array file that opens fine and contains nonsense, or a tar that will not extract.
- **fix:** tar on the VM, download the tarball. Never copy a file the job is writing.

## 11. Suppressing colab new output

- **symptom:** every later step fails with `session not found`.
- **reality:** the allocation failed and the message saying why was discarded; entitlement, capacity and concurrency need opposite responses.
- **fix:** never `>/dev/null` an allocation.
- **ref:** [05-error-taxonomy.md](05-error-taxonomy.md)

## 12. Treating an allocation error as proof nothing was allocated

- **symptom:** a retry hits 412, or an unexplained [?] VM appears.
- **reality:** a client-side ReadTimeout on `colab new` can leave a created, unnamed VM holding a concurrency slot.
- **fix:** re-list after ANY `colab new` error, before retrying.

## 13. set -e around an upload in a bootstrap

- **symptom:** the session holds tarballs but no scripts; a later step fails with `No such file or directory`.
- **reality:** the failed upload aborted the deploy before the extraction step.
- **fix:** handle upload failure explicitly with retry; do not let it abort the script.

## 14. Relying on colab exec --timeout

- **symptom:** a supervisor frozen for hours on a dropped connection, with --timeout set.
- **reality:** --timeout bounds code execution, not a lost websocket.
- **fix:** external coreutils `timeout` on every call, with a bigger budget for transfers.

## 15. Calling a session an orphan from the default store alone

- **symptom:** a healthy campaign gets stopped.
- **reality:** a campaign run with `--config <path>` keeps state there, so the default store reads {} while everything is fine. [?] means `unlabelled in the store that was loaded`.
- **fix:** harvest --config paths from running processes; build the held-endpoint set ONCE from ps args and test membership (a per-endpoint `grep ps` matches the auditing pipeline itself and gives a false negative); leave stopping unidentified sessions to a human.
- **ref:** [08-multi-account.md](08-multi-account.md)

## 16. Running two accounts through one CLI home

- **symptom:** `[colab] Pruned N stale local session(s).` and live VMs that can no longer be addressed.
- **fix:** one HOME per account/campaign.
- **ref:** [08-multi-account.md](08-multi-account.md)

## 17. Reading --auth=adc as an account

- **symptom:** work billed to the wrong account.
- **reality:** --auth picks a mechanism; CLOUDSDK_CONFIG picks the identity. There is no `colab whoami`, and ADC files often have an empty account field.
- **fix:** set CLOUDSDK_CONFIG explicitly every time; wrap each account in its own script.

## 18. Mistaking a usage throttle for exhausted credit

- **symptom:** `no quota or entitlement` for a class that worked earlier, with balance remaining.
- **reality:** a throttle after sustained heavy use of that class; it clears in ~10-26 h with no purchase. The CLI's message is its guess at an HTTP 400 on assign.
- **fix:** back off and retry later. Do not buy compute units on this evidence.

## 19. Benchmarking with tasks that are too short

- **symptom:** a CPU scaling curve that plateaus near 4x regardless of core count.
- **reality:** with sub-second tasks, process spawn dominates and the measurement is of the fork, not the machine.
- **fix:** multi-second tasks, fresh subprocesses, and do not fork from a kernel that already imported a multithreaded library (jax warns about deadlock for good reason).

## 19b. Reading a per-shape rate off an account-wide counter

- **symptom:** a shape's CU/hr comes out at an exact multiple of its real rate: two live assignments of the same shape report exactly 2x.
- **reality:** `colab usage` reports the ACCOUNT aggregate. With anything else assigned, the number is the sum, and it still looks like a plausible single-shape rate.
- **fix:** read the rate only while the probed shape is the sole live assignment: assert `Active assignments: 0` before allocating and `1` while live, and record that assertion next to the number so an aggregate cannot be published later as a rate. `scripts/run-probe.sh` refuses to start otherwise and stores `cu_rate_clean`.
- **ref:** [09-cost-and-quota.md](09-cost-and-quota.md)

## 20. Quoting code through nested shells

- **symptom:** `conditional binary operator expected`, `unexpected EOF`, a variable that silently became empty, an interpreter consuming a heredoc.
- **reality:** every layer -- local shell, remote shell, `bash -lc`, remote python -- gets a turn at the quotes.
- **fix:** write a script file and invoke it by path. For remote code use `colab exec -f file.py` or stdin. This also removes the #4 self-match trap.

## 21. Confusing `the job reported success` with `the result is right`

- **symptom:** a run completes, logs clean, numbers are wrong.
- **fix:** gate on sanity invariants the job itself fails on, and TEST that the gate fires by feeding it known-bad input once. Gate on exit status with pipefail, not on `the output file exists`. A progress counter inside an HDF5 or DB file lags the filesystem -- read progress from the artifacts.

## 22. Leaving the session running

- **symptom:** quota consumed, later allocations 412.
- **fix:** explicit `colab stop` PLUS a check that `colab usage` shows 0.00/hr and 0 active assignments.
