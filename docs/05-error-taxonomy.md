# Error taxonomy

GENERATED by `tools/gen.py` from [`spec/errors.json`](../spec/errors.json). `google-colab-cli 0.7.5`.

## Classes

| class | signal | latency | retry | action |
|---|---|---|---|---|
| **entitlement** | Backend rejected accelerator 'X' | ~1-2 s | never | different shape; re-probe occasionally, entitlements change |
| **concurrency** | TooManyAssignmentsError, HTTP 412 | fast | only after releasing | orphans count against the limit; release them |
| **capacity** | HTTP 503 | slow | later | or fall back to another shape |
| **throttle** | no quota or entitlement, balance remaining | ~1-2 s | after ~10-26 h | back off; do NOT buy compute units |
| **control-channel** | RuntimeError: Connection was lost. / empty poll | hangs | yes, idempotently | VM and job unaffected; never stop |

## Decision table

| symptom | what it is | correct response |
|---|---|---|
| Backend rejected accelerator 'X'. You may not have quota or entitlement... | entitlement: your account/tier cannot have this shape at all. Returns in ~1-2 s. | Use a different shape. Retrying never helps. Re-probe occasionally. |
| TooManyAssignmentsError: Precondition Failed (HTTP 412) | concurrency: you already hold the maximum assignments, often including forgotten orphans. | List assignments; release orphans (03 §7). Do not hammer `colab new`. -> [03-session-lifecycle.md](03-session-lifecycle.md) |
| HTTP 503 Service Unavailable from `colab new` | capacity: the shape exists for you, none free now. | Retry later or fall back. Not a quota problem. |
| ReadTimeout: ... read timeout=120 on `colab new` | client gave up; the backend may have continued. | Re-list before retrying. A VM may exist as an unnamed orphan holding a slot. |
| no quota or entitlement for a shape that worked an hour ago, balance remaining | usage throttle after sustained heavy use of one class. | Back off. Clears in ~10-26 h with no purchase. |
| RuntimeError: Connection was lost. (jupyter_kernel_client/wsclient.py) | control-channel drop. VM and job unaffected. | Retry the call. Never stop the session. -> [04-supervisor-patterns.md](04-supervisor-patterns.md) |
| `exec` hangs far past its --timeout | same; --timeout does not bound socket loss. | Only an external coreutils `timeout` saves you. |
| the FIRST `exec` on a brand-new session hangs | the command has usually already run; the reply was lost. | Idempotent launch (PID file + result check), then retry. Burn a cheap warm-up exec after allocation. |
| TimeoutError: Timeout waiting for reply | the CLI's own --timeout fired waiting on the kernel reply. It does NOT mean the code did not run. | Retry idempotently and check state. Unlike a socket loss this returns control, but it says nothing about whether the work started. |
| a timed-out `exec` | the command may already have run; only the reply was lost. | Check state before retrying. No reply is not no effect. |
| Session 'X' appears to be lost (404/401). Cleaning up. | <=0.6.0: an expired proxy token; the CLI discards a handle to a live VM. | Upgrade to >=0.7.x. Meanwhile re-adopt the assignment (03 §6). -> [03-session-lifecycle.md](03-session-lifecycle.md) |
| Session 'X' not found for a session visible in `colab sessions` | an endpoint id passed where a local label was required; or wrong HOME/--config store; or one malformed row made the store fail closed. | Check the store loaded, then the label, then validate the JSON. |
| Pruned N stale local session(s). | `colab sessions` deleted local rows the calling account cannot see. | With multiple accounts you just orphaned the other one's VMs. Use isolated homes. -> [08-multi-account.md](08-multi-account.md) |
| every session reports 'not found', including healthy ones | sessions.json failed closed -- one bad row poisons the store. | Restore a backup or remove the bad row; validate with SessionState(**row) before writing. |
| SSLEOFError: EOF occurred in violation of protocol during `upload` | large-transfer failure through the runtime proxy. | Chunk it (16 MB). -> [06-data-transfer.md](06-data-transfer.md) |
| `colab update` says you are current but --high-mem is unknown | you are on 0.6.0 from a different install path than the one checked. | `colab version`; install >=0.7.x. |
| exec: Got unexpected extra argument(s) (print(...)) | code passed positionally. Never supported. | Use -f FILE or stdin. |
| colab: command not found in a non-login shell | the CLI lives in ~/.local/bin, not on a bare PATH. | `bash -lc`, or export PATH explicitly. |
| 'Credentials' object has no attribute 'request' | you constructed the API client from raw ADC credentials. | Go through state.client. |
| pydantic validation error writing a rebuilt session row | you copied variant/accelerator/machine_shape enums into str fields. | Write the enum NAME (`.name`), not `.value`. |
| exit code 15 and no output from a restart script | `pkill -f` matched the caller's own cmdline. | Script files + bracketed patterns. -> [04-supervisor-patterns.md](04-supervisor-patterns.md) |
| gcloud auth list -> 'No credentialed accounts' | ADC files are not gcloud logins. | Not an error. Does not mean no account is configured. |

## Allocation triage

```bash
colab new -s probe --gpu X

# Backend rejected accelerator 'X' ...  -> ENTITLEMENT. ~1-2 s. Never retry; pick another shape.
# HTTP 503 Service Unavailable          -> CAPACITY. Retry later, or fall back to another shape.
# TooManyAssignmentsError: 412          -> CONCURRENCY. Check for orphans first.

colab usage                             # authoritative, side-effect-free: 'Active assignments: N'
```

## Rules

- Entitlement rejections come back fast (~1-2 s): the backend answers from policy, not placement. A slow failure is capacity or network.
- A 412 with no known sessions means orphaned assignments hold the slots. `colab usage` is the authoritative count.
- A detached job keeps running on a VM that cannot currently be addressed. Probe before rebuilding: re-bootstrapping elsewhere while the original finishes and is reclaimed loses the results.
