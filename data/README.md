# Raw measurement data

Machine-generated; not hand-edited. Consolidated machine-readable view:
[`../spec/shapes.json`](../spec/shapes.json), generated by `tools/gen.py`.

```
shapes/
  <label>.json         inventory + micro-benchmarks from agenticcolab/probe.py
  <label>.meta.json    allocation latency, CU/hr, raw `colab usage` lines, session line
  <label>.out          the probe's stdout as captured on the VM
  scaling-<label>.json CPU scaling sweep, where run
```

## Provenance

| | |
|---|---|
| CLI | `google-colab-cli` 0.7.5 (PyPI), auth `oauth2` |
| account | one paid Colab account |
| driver | 580.82.07 on all GPU shapes |
| collected by | `scripts/run-probe.sh <label> [colab new flags...]` |

Each probe allocated the shape, ran the payload detached, downloaded the JSON and released
the VM. The 11-shape sweep cost under 1 compute unit.

## `<label>.json` keys

| key | contents |
|---|---|
| `requested_accelerator` | what was requested, not necessarily what was allocated |
| `cpu` | model, logical/physical counts, SMT ratio, ISA flags |
| `memory` | `MemTotal_GiB`, `MemAvailable_GiB`, swap |
| `cgroup_limits` | cgroup v2 `cpu.max` / `memory.max`; `max` means no quota |
| `disk` | size and free for `/`, `/content`, `/tmp`, `/dev/shm` |
| `gpu` | `nvidia-smi` fields: name, VRAM, driver, compute cap, PCIe, power limit |
| `accelerator_devices` | jax's view. On a GPU runtime this reports the GPU, not a TPU |
| `torch` | version, CUDA version, device name, VRAM, SM count |
| `packages` | selected package versions + total pip count |
| `bench.cpu_gemm` | fp64 GEMM GFLOP/s, 1 thread vs all |
| `bench.gpu` | matmul TFLOP/s by dtype, HBM copy GB/s, H2D pinned vs pageable |
| `bench.tpu` | bf16 matmul TFLOP/s through `jax.jit` |
| `bench.disk` | `dd` write with `conv=fdatasync`; read is cache-warm, not device read |
| `bench.cpu_scaling` | the scaling sweep, when run inline |

## Caveats

- **One account, one day.** Entitlements, shapes and CU rates vary by subscription tier and
  change over time.
- **`CU/hr` is read from `colab usage` while the assignment is live** and returns to 0 on
  release. The reading is **account-wide**, so it is this shape's rate only when the probe
  was the sole live assignment. `cu_rate_clean` records whether that held;
  `tools/gen.py` publishes a rate only when it is true.
- **Disk read figures are page cache.** Dropping caches requires root. Only the write number
  is meaningful.
- **Micro-benchmarks characterise the machine, not a workload.**
- **`a100-highmem.json` was collected across a dropped control connection.** The payload ran
  to completion on the VM and the JSON is intact; the supervising script recorded
  `payload_complete=0` because it never saw the completion marker.

Rows from other tiers, especially free tier and any shape with no row here, are the most
useful addition. See [CONTRIBUTING.md](../CONTRIBUTING.md).
